# Project To Business Architect

## Overview
Use this skill to convert an existing project into an executable business system with clear offers, channels, metrics, and operating cadence.

## Use This Skill When
Use when the user asks to turn an idea, product, or creative project into a business with revenue, customers, and repeatable execution.
- User asks for business model, monetization, pricing, or offer design.
- User asks for GTM strategy, demand testing, or launch planning.
- User asks for business dashboard metrics, weekly operating loops, or scaling plan.
- User asks how to package a current repo/project into a sellable service/product.

## Workflow
1. Business intake.
- Define target customer, core pain, current project assets, and desired revenue model.
- Capture constraints (time, budget, channels, team, region).

2. Evidence gathering.
- Pull technical/documentation reality via `context7` when product feasibility or integration claims are involved.
- Pull internal research evidence via `notebooklm` when notebook-backed market/context data exists.
- Default NotebookLM evidence base for business mode:
- Notebook title: `Business Brain - Codex Business Operating System`
- Notebook ID: `e22302cc-1fda-4470-971a-3c1b404dc3e4`
- Separate validated evidence from assumptions.

3. Model and offer design.
- Pick business model (productized service, SaaS, content product, agency, hybrid).
- Define offer ladder (entry/core/premium), pricing hypothesis, and differentiation.
- Define minimum sellable package and delivery scope.

4. Go-to-market and demand validation.
- Build ICP-specific messaging, acquisition channels, and 30-day validation experiments.
- Define conversion funnel stages and expected benchmark ranges.

5. Operating system.
- Build 30/60/90-day plan with weekly cadence.
- Define KPI board (pipeline, conversion, retention, margin, cash runway).
- Define risk register and contingency actions.

## Safety Rules
- Never present assumptions as facts.
- Never promise legal/financial outcomes or guaranteed revenue.
- Mark financial projections as scenarios, not certainties.
- If critical market data is missing, flag uncertainty and request targeted validation.

## Resources
- Context reference server: `context7` MCP
- Research evidence server: `notebooklm` MCP
- Default business evidence notebook: `references/business_brain_notebook.md`

## Output Contract
1. Business thesis: customer, pain, differentiation, and model choice.
2. Offer and monetization plan: packages, pricing hypotheses, and margin logic.
3. GTM execution plan: channels, experiments, and funnel targets for 30/60/90 days.
4. KPI and risk board: metrics, thresholds, and mitigation actions.
